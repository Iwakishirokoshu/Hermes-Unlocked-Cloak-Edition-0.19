# Cloak Proxy Pool

Минимальное персистентное хранилище прокси, чтобы каждый новый Cloak-профиль получал свежий, неиспользованный прокси из общего пула, а агент не путался кому что выдал.

## Хранилище

Один файл — `<cloak-dir>/proxies.json`, формат массив объектов. Каталог
разрешается в таком порядке: `CLOAK_PROXY_POOL_FILE` → `CLOAK_POOL_DIR` →
`CLOAK_DIR` → `/etc/cloak/` → `$HOME/.hermes/cloak/`. В Docker-поставке
`$HOME` агента равен каталогу данных Hermes, поэтому путь не совпадает с
`/root/`. Никогда не вписывай путь руками — спроси его у инструмента.

```json
[
  {"url": "http://user:pass@1.2.3.4:8080", "assigned_to": "acc-001", "used_at": "2026-06-19T22:30:00Z"},
  {"url": "http://user:pass@5.6.7.8:8080", "assigned_to": null,      "used_at": null}
]
```

## Основной путь — инструмент `cloak_proxy_pool`

Он работает с тем же файлом и той же блокировкой, не зависит от путей и
не требует терминала. Используй его по умолчанию.

```text
cloak_proxy_pool(action="add", text="<строки прокси, по одной на строку>")
cloak_proxy_pool(action="list")     # → count, strategy, auto_assign, masked-список
cloak_proxy_pool(action="clear")
```

`action="next"` / `action="release"` вручную вызывать не нужно —
`cloak_create_profile(use_pool=true)` резервирует прокси сам.

## CLI хелпер (только вне Cloak toolset)

`pool.py` лежит в каталоге самого скилла. Путь бери из окружения, а не из
этого документа:

```bash
POOL_PY="$(find "$HOME" /opt/hermes -maxdepth 4 -path '*cloak-proxy-pool/pool.py' -print -quit)"

python3 "$POOL_PY" load <<'EOF'
1.2.3.4:8080:user:pass
socks5://user:pass@13.14.15.16:1080
EOF

python3 "$POOL_PY" status              # total / free / used
python3 "$POOL_PY" next <profile_name> # атомарно выдать и пометить assigned_to
python3 "$POOL_PY" release <profile_name>
```

Все операции атомарные (временный файл + rename), так что параллельные
регистрации не перетрут друг друга.

## Поддерживаемые форматы при `load`

| Что прислал юзер | Парсится как |
|---|---|
| `1.2.3.4:8080` | `http://1.2.3.4:8080` |
| `1.2.3.4:8080:user:pass` | `http://user:pass@1.2.3.4:8080` |
| `user:pass@1.2.3.4:8080` | `http://user:pass@1.2.3.4:8080` |
| `http://...` / `https://...` / `socks5://...` | как есть |

Пустые строки и комментарии (`#`) игнорируются. Один прокси на строку.

## Когда юзается

1. **Оператор прислал пул в чат** («вот прокси, загрузи»):
   - `cloak_proxy_pool(action="add", text=...)`, затем `action="list"` —
     подтвердить количество и назвать, какие строки не распознались.

2. **Нужен профиль с прокси из пула**:
   - `cloak_create_profile(name=..., use_pool=true)`. Инструмент сам атомарно
     выберет свободный прокси и закрепит его за именем профиля.
   - Не вызывай перед этим `action="next"` — получится лишняя резервация,
     которую никто не освободит.

3. **Профиль больше не нужен**:
   - `cloak_stop(profile=...)` возвращает прокси в пул.
   - `action="release"` нужен только для внешнего workflow, который сам делал
     `action="next"`.

## Что не делать

- Пул не обязателен. Если оператор прислал конкретный прокси в чат, передавай
  его напрямую как `proxy=...` — явное значение всегда сильнее пула.
- Не заводи собственную ротацию поверх пула: резервации живут в одном файле с
  межпроцессной блокировкой, и параллельная самодельная выдача её сломает.
- `socks4` не поддерживается — CloakBrowser его не умеет, переименование схемы
  не поможет.

## Связи с другими скиллами

Создание и остановка профилей описаны в [[cloak-profiles]]. Прокси берутся и
возвращаются только через этот общий пул.
